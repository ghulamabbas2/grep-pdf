# grep.pdf

Search, chat, and get cited answers from your PDFs. Upload a document, ask a
question, and get an answer grounded in the source text with links back to
the exact page it came from.

`grep-pdf` is a monorepo pairing a **FastAPI** backend with a **React + Vite +
TypeScript + Tailwind** frontend, backed by **Postgres/pgvector** for
retrieval and **Clerk** for authentication.

```
grep-pdf/
├── backend/    # FastAPI app (routers, services, models, schemas) — managed with uv
├── frontend/   # React + Vite + TS + Tailwind
├── docs/       # Architecture, API, auth, database, deployment, and other conventions
├── Dockerfile  # Multi-stage build: React bundle → FastAPI image (used by Railway)
└── package.json  # Root dev runner
```

## Features

- **PDF upload & processing** — parse PDFs with PyMuPDF, chunk (~800 tokens,
  100-token overlap), and embed with Voyage `voyage-3-lite`.
- **Retrieval-augmented chat** — ask questions about an uploaded PDF and get
  answers generated by Claude (via LangChain `ChatAnthropic`), grounded in
  the top-6 most relevant chunks (cosine similarity over pgvector).
- **Structured citations** — every answer cites the exact page and character
  offsets it was drawn from, streamed to the client as SSE events.
- **Per-user auth & scoping** — Clerk-backed sign-in; every database query
  and uploaded file is scoped to the signed-in user.

## Tech stack

| Layer | Technology |
|-------|------------|
| Backend | FastAPI, SQLAlchemy, Alembic, Postgres + pgvector, Python 3.13 (uv) |
| Frontend | React 19, Vite, TypeScript, Tailwind v4, React Router |

## Prerequisites

- [uv](https://docs.astral.sh/uv/) (Python 3.13)
- Node.js 20+ and npm
- A local **Postgres** instance with the **pgvector** extension available
- API keys for **Clerk**, **Voyage AI**, and **Anthropic** (see below)

## Getting started

### 1. Clone and configure environment variables

```bash
cp backend/.env.example backend/.env
cp frontend/.env.example frontend/.env
```

Fill in the required values:

| File | Variable | Where to get it |
|------|----------|------------------|
| `backend/.env` | `DATABASE_URL` | Your local Postgres connection string (pgvector extension enabled) |
| `backend/.env` | `CLERK_SECRET_KEY` | Clerk Dashboard → API keys |
| `backend/.env` | `VOYAGE_API_KEY` | [Voyage AI](https://www.voyageai.com/) dashboard |
| `backend/.env` | `ANTHROPIC_API_KEY` | [Anthropic Console](https://console.anthropic.com/) |
| `frontend/.env` | `VITE_CLERK_PUBLISHABLE_KEY` | Clerk Dashboard → API keys |

The rest of the variables in `.env.example` have sensible local defaults —
see the inline comments in each file for details.

### 2. Create the database

```bash
createdb grep_pdf
psql grep_pdf -c "CREATE EXTENSION IF NOT EXISTS vector;"
```

Adjust the database name/credentials to match `DATABASE_URL` if you changed it.

### 3. Install dependencies

```bash
npm install && npm run setup
```

This installs the root runner, then `uv sync`s the backend and `npm install`s
the frontend.

### 4. Run migrations

```bash
cd backend && uv run alembic upgrade head
```

### 5. Start the dev servers

```bash
npm run dev
```

This runs backend and frontend concurrently:

- **Backend** → http://localhost:8000 (health check: `/api/health`)
- **Frontend** → http://localhost:5173

The frontend proxies `/api/*` to the backend (`frontend/vite.config.ts`), so
the browser talks to a single origin (`:5173`) during development.

You can also run each side independently:

```bash
# Backend only
cd backend && uv run fastapi dev app/main.py

# Frontend only
cd frontend && npm run dev
```

## Everyday commands

**Backend** (from `backend/`):

```bash
uv run fastapi dev app/main.py   # dev server with reload
uv add <package>                 # add a dependency
uv run ruff check                # lint
uv run ruff format               # format
uv run pytest                    # unit tests
uv run alembic revision --autogenerate -m "..."   # new migration
uv run alembic upgrade head      # apply migrations
```

**Frontend** (from `frontend/`):

```bash
npm run dev       # Vite dev server
npm run build     # tsc -b type-check, then vite build
npm run lint      # oxlint
npm run preview   # serve the production build
```

## Testing

- **Backend unit tests** — `pytest`, colocated as `test_*.py` next to the
  code they test. Run with `cd backend && uv run pytest`.
- **Frontend unit tests** — `Vitest`, colocated as `*.test.ts`. Run with
  `cd frontend && npm run test`.
- **End-to-end QA** — driven live through Playwright MCP against the real
  backend; there is no committed `.spec.ts`/`e2e` suite. Point QA at
  `backend/.env.test` (a separate database), never dev or prod data.

See [docs/testing.md](docs/testing.md) for details.

## Deployment

Deployed on **Railway** via its native GitHub integration — Railway builds
the Docker image and deploys on push; **GitHub Actions only runs CI**
(lint, type-check, tests), never the build or deploy itself.

- Every PR gets an **isolated preview environment** (own URL, Postgres
  database, and storage volume), automatically torn down when the PR closes.
- Merging to `main` deploys to production.
- A single `Dockerfile` builds the React frontend and bundles it into the
  FastAPI image; one `uvicorn` process serves both the SPA and `/api`.
- Alembic migrations run automatically on container start, before the app
  boots.

See [docs/deployment.md](docs/deployment.md) for the full build, CI, and
environment-variable reference, and [docs/git-conventions.md](docs/git-conventions.md)
for the branch → PR → preview-review flow required before merging.
